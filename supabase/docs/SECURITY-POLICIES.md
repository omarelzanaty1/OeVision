# سياسات الأمان (RLS)
RLS مفعّل على الجداول الستة كلها، وعلى `storage.objects`. الصلاحيات على مستوى الأعمدة مقيّدة أيضًا (طبقتا حماية).

| الجدول | زائر (anon) | عميل | مدير |
|---|---|---|---|
| profiles | لا شيء | قراءة ملفه، تعديل `full_name` و`avatar_url` فقط | قراءة الكل |
| admins | لا شيء | يرى 0 صفوف، لا كتابة | قراءة فقط. الكتابة عبر `grant_admin` فقط |
| projects | المنشور فقط | المنشور فقط | قراءة/إضافة/تعديل/حذف الكل |
| project_requests | لا شيء | إضافة طلبه (status=new فقط)، قراءة طلباته، لا تعديل ولا حذف | قراءة الكل، تعديل `status` فقط، حذف |
| request_attachments | لا شيء | إضافة لطلبه ومسار مجلده فقط، قراءة مرفقاته، حذفها ما دام الطلب `new` | قراءة وحذف الكل |
| contact_messages | إضافة فقط (user_id فارغ) | إضافة | قراءة وحذف |

## حماية الأدوار
- `role` لا يمكن تغييره من أي مستخدم؛ يتغير فقط تلقائيًا عند إضافة/حذف صف في `admins`.
- لا يمكن وجود أكثر من حسابين Admin، ولا تعديل صف admins بعد إنشائه.
- المدير لا يستطيع تعديل إجابات العميل، فقط الحالة.
- دالة `is_admin()` تقرأ هوية المستخدم من JWT داخل قاعدة البيانات.

## ملاحظات
- أي مستخدم مسجّل يستطيع إنشاء طلبات (بحد 20 يوميًا). رسائل Contact مفتوحة للزوار ولا يوجد Rate Limit عليها في قاعدة البيانات، فيُنصح بـ CAPTCHA (انظر AUTH-SETUP.md).
- **Security Advisors** (فُحصت بعد التنفيذ): تنبيهان فقط من نوع WARN، وكلاهما عن `is_admin()` كونها قابلة للاستدعاء من anon وauthenticated. هذا مقصود: سياسات RLS تستدعيها بصلاحية المستخدم نفسه، وهي تُرجع فقط true/false عن هوية المتصل ولا تكشف أي بيانات. لا تنبيهات أخرى (لا جدول بلا RLS ولا دالة أخرى مكشوفة).
